# 데이터 수집 순환 주기 (Collection Cycle)

> JobMarketRadar · 워크넷 채용정보 자동 수집 파이프라인 정리
> 작성일: 2026-07-08

---

## 1. 한 줄 요약

서버(`server.js`)가 켜져 있는 동안 **매일 2회(오전 9시·오후 9시)** 워크넷 API를 호출해
채용공고를 **갱신(업서트)** 한다. 한 번 수집 시 전체 목록 → 상세 → DB 저장까지 약 1~2분.

---

## 2. 자동 수집 주기 (cron)

```js
// server.js
const CRON_SCHEDULE = process.env.CRON_SCHEDULE || '0 9,21 * * *'; // 1일 2회
```

| 항목 | 값 |
|---|---|
| 스케줄 표현 | `0 9,21 * * *` |
| 의미 | 매일 **09:00, 21:00** (로컬 시간) |
| 라이브러리 | `node-cron` |
| 변경 방법 | `.env`의 `CRON_SCHEDULE` 수정 후 서버 재기동 |
| 검증 | 서버 기동 시 `cron.validate()` 통과해야 등록 (잘못되면 자동수집 비활성화 경고) |

### 주기 변경 예시
```bash
# 6시간마다 (1일 4회)
CRON_SCHEDULE=0 */6 * * *

# 매 정시
CRON_SCHEDULE=0 * * * *

# 오전 9시 1회만
CRON_SCHEDULE=0 9 * * *
```

## 3. 한 번 수집 사이클 (1회 동작 흐름)

```
┌─────────────────────────────────────────────────────┐
│  cron 트리거 (09:00 또는 21:00)                      │
│        ↓                                             │
│  collector.run() 실행                                │
│        ↓                                             │
│  ① 목록 API (callTp=L)                               │
│     · 페이지당 100건(DISPLAY)씩 전체 페이지 순회      │
│     · 페이지 사이 200ms 대기 (API 호출 제한 대응)      │
│     · 실패 시 2회 재시도 (withRetry)                  │
│        ↓                                             │
│  ② 상세 API (callTp=D)                               │
│     · 각 공고별 상세 조회                              │
│     · 직종/지역/경력/학력/고용형태 등 추출              │
│     · 공고당 200ms 대기                               │
│        ↓                                             │
│  ③ DB 업서트 (upsertPosting)                          │
│     · 트랜잭션: 공고 헤더 upsert + 모집직무 N행 갱신    │
│     · 같은 emp_seqno → 갱신 / 새 번호 → 추가           │
│        ↓                                             │
│  ④ 수집 이력 기록 (collection_logs)                   │
│     · run_at, mode, fetched_count, status            │
└─────────────────────────────────────────────────────┘
```

### 핵심 상수 (`collector.js`)
| 상수 | 값 | 의미 |
|---|---|---|
| `DISPLAY` | 100 | 목록 API 한 페이지당 건수 (최대 100) |
| `SLEEP_MS` | 200ms | API 호출 사이 대기 (과다호출 차단 방지) |
| `withRetry` | 2회 | API 실패 시 재시도 횟수 |
| `startPage` 상한 | 1000 | API 정책상 목록 페이지 최대 |

## 4. 데이터 갱신 방식: 업서트(upsert)

- 기준 키: **`emp_seqno` (공개채용공고순번, 워크넷 원본 고유키)**
- 동작:
  - 이미 DB에 있으면 → 최신 정보로 **갱신** (모집직무는 기존 행 삭제 후 재삽입)
  - 새 공고면 → **추가**
- **삭제는 하지 않음** → 워크넷 목록에서 빠진(마감된) 공고도 DB엔 남아 있음
  - 그래서 DB 건수가 워크넷 실시간 목록 건수보다 점점 많아짐 (정상 동작)

## 5. 현재 상태 (2026-07-08 기준)

### 수집 이력 (`collection_logs`)
```
2026-07-07 04:49  list      1건   success
2026-07-07 04:42  backfill  246건 success  ← 최초 대량 수집
```
→ **7/7 이후 cron 자동 수집이 안 돌았음** (labport 서버 재기동으로 cron 스케줄이 끊김)

### 수동 수집으로 갱신 완료 (2026-07-08)
- 워크넷 실시간 목록: **236건** (마감 공고 일부 빠짐)
- 수동 backfill 결과: 성공 236 / 실패 0
- DB 갱신: 공고 **246 → 263건**, 모집직무 **339 → 368건**
  (upsert라 과거 공고는 남고 + 새 공고 17건 추가)

## 6. labport 환경에서의 주의점 ⚠️

1. **서버가 꺼지면 cron도 멈춘다**
   - labport는 작업 중 서버를 자주 재기동 → 09:00/21:00 정각에 서버가 안 떠 있으면 수집 누락
2. **수동 수집이 사실상 주 갱신 수단**
   - 정확한 최신 데이터가 필요하면 `node collector.js --backfill` 로 직접 갱신
3. **DB는 계속 커진다**
   - 마감 공고가 삭제되지 않으므로, 장기 운영 시 주기적 정리(or `end_dt` 기준 만료 필터) 고려

---

## 7. 수동 수집 명령

```bash
# 전체 재수집 (백필) — 약 1~2분 소요
node collector.js --backfill

# 건수 제한 수집 (테스트용)
node collector.js --limit=10

# 또는 npm 스크립트
npm run collect
```

수집 중 진행 로그가 실시간으로 출력되며, 완료 후 `collection_logs`에 이력이 남는다.

## 8. 관련 파일
| 파일 | 역할 |
|---|---|
| `collector.js` | 워크넷 API 호출 → 파싱 → DB 저장 (수집 본체) |
| `server.js` | cron 스케줄 등록 + `/api/admin/collect` 수동 트리거 엔드포인트 |
| `db.js` | `upsertPosting()` (업서트), `logCollection()` (이력 기록) |
| `.env` | `DHS_API_KEY` (인증키), `CRON_SCHEDULE` (주기, 선택) |
| `collection_logs` 테이블 | 수집 실행 이력 (운영/디버깅) |
