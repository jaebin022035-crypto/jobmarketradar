# Step 5: 연동·디테일

> **기간: 1일** · 이 단계의 목표: 프로토타입을 실데이터로 처음부터 끝까지 점검하고, 트렌드 요약 텍스트 로직과 디테일을 다듬어 "완성본(로컬)"을 만든다.

---

## 📌 이 단계의 목표

지금까지 만든 수집기·API·프론트를 **실제 워크넷 데이터로 처음부터 끝까지 돌려본다**. 이 과정에서 "데이터가 비어있다", "특정 직종이름이 깨진다", "요약 텍스트가 이상하다" 같은 **실사용 디테일**이 드러난다. 이 단계를 거쳐야 "데모 가능한 완성본"이 된다.

완료하면:
- ✅ 전체 파이프라인(수집→저장→API→차트) 실데이터로 end-to-end 검증
- ✅ "이번 주 트렌드 요약" 자동 텍스트 로직 완성
- ✅ 빈 데이터/이상치/긴 텍스트 등 엣지케이스 처리
- ✅ UI 디테일 마감 (폰트, 간격, 색, 마이크로인터랙션)
- ✅ 로컬에서 데모 가능한 상태

## 🚶 진행 순서 (단계별)

### 1. 전체 흐름 end-to-end 테스트

처음부터 끝까지 한 번에 돌려본다:
1. `node collector.js` → 데이터 수집 (DB 확인)
2. `bash start_server.sh` → 서버 기동
3. 브라우저 접속 → 대시보드 표시 확인
4. 차트가 **실제 수집한 데이터**를 반영하는지 확인

> 💡 이때 "수집은 됐는데 차트가 안 그려진다", "숫자가 안 맞는다" 같은 **통합 버그**가 집중적으로 터진다.

### 2. 데이터 정합성 검증

API가 주는 숫자와 DB 실제 카운트가 같은지 비교:
```bash
# DB 직접 카운트
sqlite3 app.db "SELECT job_category, COUNT(*) FROM job_postings GROUP BY job_category ORDER BY 2 DESC LIMIT 5;"
# → /api/trends/category 결과와 동일해야 함
```
안 맞으면 WHERE 조건/기간 계산 로직 버그.

### 3. 트렌드 요약 텍스트 로직 (`/api/insight/weekly`)

이 프로젝트의 **인사이트 기능** (계획서 2절 ★★). 집계 데이터를 보고 **사람이 읽을 수 있는 문장**을 만든다.

구현 아이디어 (복잡한 LLM 없이도 가능):
```js
function buildWeeklyInsight(data) {
  const top = data.topCategories[0];
  const surge = data.biggestRiser;     // 전주 대비 증가 폭 큰 직종
  return `이번 주에는 '${top.name}' 직종 공고가 가장 많았습니다 (${top.count}건).
          특히 '${surge.name}' 공고가 지난주 대비 크게 늘었습니다.`;
}
```

> 💡 규칙: 통계 수치를 **문장으로 풀어서** 보여준다. 포트폴리오에선 "데이터 기반 인사이트 자동 생성"이라는 어필이 됨.

### 4. 빈 데이터 케이스 점검

| 상황 | 처리 |
|---|---|
| 수집 전 (DB 텅 빔) | "데이터 수집 중입니다. 잠시 후 새로고침해 주세요" |
| 필터 결과 0건 | "해당 조건의 공고가 없습니다. 필터를 변경해 보세요" |
| 특정 직종 데이터만 부족 | 차트는 표시, 빈 카테고리는 생략 |

> ⚠️ 이 케이스가 빠지면 **처음 데모를 켜는 순간 빈 화면**만 보여 "고장났다"는 인상을 준다.

### 5. 이상치 처리

워크넷 데이터의 특이점:
- **급여 0 또는 비어있음** → "급여 협의" 또는 차트에서 제외
- **경력 null** → "경력무관" 처리
- **직종코드 미상** → "기타"로 묶기

### 6. 긴 텍스트/특수문자 점검

- 회사명에 특수문자, HTML 엔티티가 섞일 수 있음 → 안전하게 출력 (XSS 방지: `textContent` 사용)
- 직종명이 너무 길면 말줄임 처리

### 7. 차트/색상 디테일 마감

- 차트 **색 팔레트**를 직종별로 일관되게
- 폰트 크기/범례 위치 정돈
- 툴팁(마우스 오버 시 상세) 추가

### 8. 모바일 최종 확인

좁은 화면에서 차트가 깨지지 않는지, 필터 패널이 잘 동작하는지 확인.

### 9. 출처/한계 명시

대시보드 하단에 (계획서 11절 리스크 대응):
> "본 통계는 워크넷 등록 공고 기준이며, 전체 채용시장을 대변하지 않습니다."

## ⚠️ 주의사항

1. **🔗 end-to-end를 꼭 한 번에 돌릴 것** — 부분별로는 잘 되어도 합치면 터지는 버그가 있음.
2. **🔢 정합성은 직접 카운트로** — API가 주는 숫자를 맹신하지 말고 DB와 비교.
3. **📝 요약 텍스트는 자연스럽게** — 기계문 같으면 안 됨. 수치가 큰 걸 먼저 언급.
4. **🚫 빈 화면 방어** — 수집 전/필터 결과 없음은 반드시 안내 메시지.
5. **🛡️ XSS 주의** — 외부 데이터(회사명 등)를 `innerHTML`로 직접 넣지 말 것. `textContent` 사용.
6. **🎨 데모 관점에서 보기** — "발표날 처음 켜는 사람" 입장에서 빈 곳/어색한 곳 찾기.
7. **📊 과대 해석 경고** — "이게 시장 전부다" 식의 표현 금지. 출처/한계 명시.
