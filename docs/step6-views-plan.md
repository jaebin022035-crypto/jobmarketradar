# Step 6: 3뷰 구조 설계 (내비게이션 + 인사이트 + 맞춤공고)

> JobMarketRadar · 목적별 뷰 분리 설계
> 작성일: 2026-07-08

---

## 1. 배경

기존 단일 스크롤 페이지(요약+필터+차트+공고목록)를 **목적별 3개 뷰**로 분리.
- 데이터 탐색 → 대시보드
- 통찰 도출 → 인사이트
- 구직자 행동 → 맞춤 공고

## 2. 전체 구조

```
┌──────────────────────────────────────────────────┐
│  [헤더: JobMarketRadar]                          │
│  ┌────────────────────────────────────────────┐  │
│  │ 📊 대시보드 │ 💡 인사이트 │ 🎯 맞춤 공고  │  │ ← 내비게이션 탭
│  └────────────────────────────────────────────┘  │
│  ┌────────────────────────────────────────────┐  │
│  │   (선택한 탭의 뷰)                          │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

- **방식:** SPA — 단일 `index.html`에서 탭 클릭 시 뷰 show/hide 전환
- **이유:** labport 규칙(루트=index.html) 준수, 새로고침 없이 빠름, 별도 HTML 불필요

## 3. 뷰 1: 대시보드 (기존 유지)
요약카드 + 필터(기간/기업/지역/직종/IT) + 차트 5개 + 공고목록.

## 4. 뷰 2: 인사이트 페이지 (C·D·F)

### C. 경력·학력
- "IT 신입 vs 경력 수요" 강조 카드 (신입+인턴 > 경력)
- IT 학력 요건 도넛 (대졸4년/석박사/학력무관)
- 문구: "현재 IT는 신입 채용 활발, 단 R&D 성격이라 석박사 비중도 높음"

### D. 지역
- IT 지역 집중도 차트 (서울 53% 강조)
- 수도권 vs 비수도권 비교 카드

### F. 전체 vs IT 비교 ⭐
- 학력 요건 / 서울 집중도 / 정규직 비중 비교
- 프론트에서 `/api/summary` + `/api/summary?itOnly=1` 두 번 호출 → 새 API 불필요
- 문구: "IT는 평균보다 학력 요건이 높고 서울에 집중"

> ⚠️ "IT 직군 31건 기준 참고용 통계" 명시 (표본 작음 솔직 표기)

## 5. 뷰 3: 나만의 맞춤 공고 (G)

```
┌─ 내 조건 ──────────────────────┐
│ 지역:     [서울 ▼]             │
│ 경력:     [☑ 신입 가능]        │
│ 학력:     [☑ 학력무관 포함]    │
│ 고용형태: [☑ 정규직]           │
│ IT직군:   [☑ IT·개발만]        │
│ ⚡ 빠른 선택: [서울 신입 정규직]│
└────────────────────────────────┘
        ↓ 매칭
┌─ 나에게 맞는 공고 (N건) ───────┐
│ [로고] OO소프트웨어            │
│        백엔드 개발자 신입       │
│        [서울][정규직][신입][IT] │ ← 매칭 하이라이트
│                        지원하기→│
└────────────────────────────────┘
```

- 기존 `/api/postings` 교차 필터 재사용
- 카드 클릭 → 워크넷 원본(`source_url`) 이동 (대시보드와 동일 로직)
- 내 조건 **로컬스토리지 저장** → 재방문 시 유지
- 차별점: "조건 저장 + 매칭 하이라이트" (기존 필터와의 차이)

### 카드 → 워크넷 이동 흐름
```
매칭 카드 클릭 → source_url(워크넷 원본) 이동 → 워크넷에서 실제 지원
```
우리 역할: "맞는 공고를 찾아 워크넷까지 데려다줌". 실제 지원은 워크넷(로그인 필요).

## 6. 서버 변경 (최소)
- C·D: 기존 API(`?itOnly=1`)로 충분
- F: 프론트 두 번 호출 비교 → 새 API 불필요
- G: `/api/postings` 교차 필터 재사용

## 7. 구현 순서
1. 내비게이션 + 뷰 전환 골조 (`index.html` 탭 바, `app.js` 라우터, `style.css`)
2. 인사이트 페이지 (C·D·F)
3. 맞춤 공고 페이지 (G)
4. 검증 + 캐시 버전업 + 커밋

## 8. 데이터 한계 (솔직 표기)
- IT 직군 31건 → 표본 작아 통계는 참고용
- `job_category` 첫 직종값만 → IT 실제 공고는 더 있을 수 있음
- 모집인원 22%만 기재 → 규모 인사이트 신뢰도 낮음
- `recruit_summary` 0% → 직무 상세 인사이트 불가
