왜 이 기술인가

각 선택에는 실무적 이유가 있다 — "유명해서"가 아니라 이 프로젝트의 제약에서 나온 판단.

SQLite + better-sqlite3 DATA

쓰기가 수집 배치(1일 2회), 읽기가 대시보드 조회 — 트래픽이 동시성을 요구하지 않는다. PostgreSQL을 두면 컨테이너 하나가 늘고 백업·마이그레이션 이슈가 생긴다. WAL 모드로 읽기-쓰기 잠금 충돌을 피하고, better-sqlite3의 동기 API 덕분에 쿼리 결과를 그대로 return하는 라우트 코드가 된다 (await 없음). 파일 하나가 곧 백업 본체.

바닐라 JS (프레임워크 없음) FRONT

화면 4개(대시보드·공고목록·인사이트·이력서)로 상태가 단순하다. React를 넣으면 빌드 파이프라인·가상DOM 오버헤드가 생기는데, 이 앱은 데이터가 바뀌면 fetch로 다시 그리는 패턴으로 충분하다. 결과물은 app.js 하나 — CDN에서 Chart.js만 받고 나머지는 전부 서버가 뿌린다.

Node 내장 crypto AUTH

비밀번호는 scrypt(N=16384)로 per-user salt와 함께 해시, 세션 토큰은 SHA-256으로 한 번 더 해시해 DB 저장 — 평문 토큰이 디스크에 안 남는다. bcrypt를 쓰면 native 빌드 이슈가 생기는데, Node 20의 내장 scrypt는 OWASP 권장 파라미터를 그대로 쓸 수 있어 의존성 0개로 같은 안전성을 얻는다.

Gemini 2단 모델 AI

공고 원문 정제는 기계적이라 flash-lite(빠름·저가)로 충분하고, 요건 분석과 자소서 문장 생성은 품질이 곧 상품이라 flash(일반)를 쓴다. 두 모델 모두 JSON 모드와 url_context를 지원함을 실측하고 도입. SDK 없이 REST로 직접 호출 — 모델 교체는 환경변수 한 줄.

멀티스테이지 Docker INFRA

better-sqlite3는 native 모듈이라 빌드에 python·make·g++이 필요하지만 런타임에는 필요 없다. 빌드 단계에서만 도구를 깔고 node_modules와 정적파일만 최종 이미지로 복사 — 이미지가 작고 공격면도 줄어든다.

ArgoCD GitOps OPS

매니페스트는 Git에, 클러스터는 그것을 따라오게(selfHeal) 만들었다. kubectl로 직접 고치면 그 변경은 언제든 Git에 의해 지워진다 — GEMINI 키 env를 수동 주입했다가 Git과 어긋난 경험 때문에 매니페스트로 옮겼다. 배포 이력 = 커밋 이력이라 롤백이 git revert다.

보안 설계

Step 8에서 세운 원칙들. 전부 코드로 검증된 동작이다.

소유자 스코프 ISOLATION

모든 프로필·자소서 쿼리가 ownerId를 같이 받는다. 남의 리소스에 접근하면 403이 아니라 404로 응답 — 존재 자체를 노출하지 않아 ID 열거 공격(enumeration)이 불가능하다.

차단 도메인 정책 CRAWL

사람인·원티드는 AI URL 조회에서 자동 제외된다 (robots.txt·CloudFront 실측 근거). 서버가 채용 사이트를 직접 fetch하지 않는다 — IP 차단 위험과 무관하게 지키는 원칙.

시크릿 관리 SECRET

API 키는 환경변수로만 주입. Git·이미지 어디에도 존재하지 않으며 커밋 전 실제 키 값으로 전체 파일 대조하는 검사를 돌린다. 쿠키는 HttpOnly + SameSite=Lax.

로그인 실패 응답 통일 AUTH

아이디 불일치·비밀번호 불일치를 같은 메시지로 응답해 어떤 계정이 존재하는지 추측하게 하지 않는다. 가입 중복만 409로 구분.
