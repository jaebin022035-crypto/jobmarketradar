수동 개입 지점 3곳

자동화가 못 미치는 지점. 주황색으로 표시한 이유가 각각 있다.

PUSHgit push 인증

Gitea 계정이 비밀번호 로그인 불가 상태. credential helper도 없어 일반 push는 프롬프트에서 무한 대기한다. ArgoCD repo secret(repo-3176879643)의 토큰을 Basic 헤더로 실어 보낸다.

ROLLrollout restart

이미지 태그가 늘 latest라 Deployment 스펙은 변하지 않고, ArgoCD는 이미지 교체를 감지하지 못한다. 빌드·push 후 반드시 직접 재시작한다.

SECRjobradar-secret

Vault에 경로가 없어 ExternalSecret 대신 수동 생성. Git에 두면 키 유출, ExternalSecret을 두면 동기화 실패로 기존 키가 깨진다 — 그래서 ignoreDifferences로 ArgoCD가 data 필드를 못 건드리게 막아둔 상태.

INITinit-db 시드

PVC가 비어 있을 때만 이미지 속 시드 DB를 복사해 마이그레이션한다. 데이터가 있으면 건드리지 않으므로 재배포해도 수집 이력이 유지된다.

§

운영 가드레일 — 실제 사고에서 나온 규칙

실제로 겪은 5건. 각 항목은 그날의 장애 원인과 복구 커밋으로 연결된다.

32Mi컨테이너 최소 메모리

vcluster 호스트 정책상 memory request가 32Mi 미만이면 pod-syncer가 Pod 생성을 거부한다. initContainer에 16Mi를 지정했다가 약 3분 서비스 다운 (5018172로 복구).

DIFFpush 전 워킹트리 검증

git checkout -f는 로컬 수정을 조용히 되돌린다. 원격 이력을 받아온 뒤 커밋하면 GEMINI env 블록이 유실됐다 — push 전 git diff 확인이 필수 (ff7df43로 복구).

PRUNGit에 없으면 지워진다

prune+selfHeal이 켜져 있어 kubectl set 같은 수동 클러스터 변경은 언제든 Git 상태로 되돌려진다. 수동 우회 대신 매니페스트를 고쳐서 push한다.

WHY없는 파일의 이유를 읽기

00-namespace.yaml·40-externalsecret.yaml은 "못 올린 것"이 아니라 구조상 뺀 것. 삭제 커밋 메시지를 먼저 읽었어야 했다 — 실수로 복원했다가 6afb53c로 되돌림.

MERGdevelop → main 병합 전 deploy/ 감사

2026-09-11, 세션 하트비트 커밋(1dc979d)에 00·40 파일이 다시 따라 들어와 있었다 — 기능 브랜치에서 오래된 main 상태를 참고해 생긴 유입. main 병합 전 git diff main..develop -- deploy/로 신규 매니페스트 유무를 확인한다.

배포 후 검증

네 고리가 모두 같은 것을 가리키는지 확인하는 순서 — 로컬 Git, Gitea, Harbor, 실행 Pod.

pipeline-check
# 1. Git — 로컬 HEAD와 Gitea main이 같은가
$ git rev-parse HEAD && git ls-remote https://std-gitea.kopoctc.kr/kopo13/web.git refs/heads/main

# 2. ArgoCD — 최신 커밋에 Synced/Healthy인가
$ kubectl get application jobradar -n argocd

# 3. 이미지 — 실행 Pod digest = 방금 push한 digest인가
$ kubectl get pod -n jobradar -o jsonpath='{..imageID}'

# 4. 서비스 — 외부 URL이 살아있는가
$ curl -sk https://kopo13-jobradar.std.kopoctc.kr/api/summary | head -c 120

# 재배포 (매니페스트 변경 후 즉시 반영)
$ kubectl annotate application jobradar -n argocd argocd.argoproj.io/refresh=normal --overwrite
